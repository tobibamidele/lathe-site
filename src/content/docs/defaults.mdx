## Kinds of default

```go
s.Enum("role", "admin", "member").Default("member")   // constant
s.Bool("active").Default(true)
s.Int("karma").Default(0)
s.Timestamp("created_at").DefaultNow()                 // current time
s.UUID("id").PrimaryKey().DefaultUUID()                // random UUID
s.Text("slug").DefaultExpr("gen_random_uuid()::text")  // raw SQL, verbatim — not portable across dialects
s.Text("id").PrimaryKey().DefaultFunc(GenerateProjectID) // calls GenerateProjectID per insert
```

`Default(v)` accepts strings, bools, integers, floats and anything with a `String()` method (such as `decimal.Decimal`).

## When Create leaves a column out

A Go zero value is sometimes a real value (`false`, `0`), so [`Create`](/docs/writing) never silently replaces one with a constant default. It leaves a column out of the `INSERT` — letting the database fill it in — only when zero means "not set":

- auto increment keys,
- columns defaulting to `now`, a UUID or an expression,
- string, enum, time and JSON columns with a constant default, when the field is empty (`Currency: ""` means "use `'USD'`"),
- **nullable** columns with any default, when the pointer is `nil`.

So a `Bool` column `Active` with `Default(true)` inserts whatever you set — `false` unless you say otherwise — and so does an `Int` column `Karma` with `Default(0)`. To get a bool or number default from the database instead, make the column `Nullable()` and leave the pointer `nil`.

```go
u := db.User{Email: "ann@example.com", PasswordHash: hash}
// Role, Active and CreatedAt are all left at their zero value.
client.Users.Create(ctx, &u)
// u.Role is now "member", u.Active is whatever the database default is
// for a *nullable* bool, u.CreatedAt is now.
```

## UUID defaults are generated in Go

`DefaultUUID()` does not rely on the database. Generated code fills a zero UUID with `uuid.New()` before the row is inserted, whenever the field is still its zero value:

```go
// generated, do not edit
Default: func(m *Post) { if m.ID == uuid.Nil { m.ID = uuid.New() } }
```

This exists because MySQL has no `RETURNING`, so a value the database generated could not be read back afterwards. Generating it in Go means the value is known immediately, on every dialect, and the column keeps its own database default for rows inserted by other tools.

## Function defaults (DefaultFunc)

`DefaultFunc` is the type-checked sibling of `Default`: it takes a package-level function that must return exactly the column's Go type, so a mismatched default is a compile error. `s.Text(...).DefaultFunc(GenerateProjectID)` requires `func GenerateProjectID() string`, and `s.UUID(...).DefaultFunc(GenerateID)` requires `func GenerateID() uuid.UUID`.

| Column builder | `f` must return |
| --- | --- |
| `Text`, `VarChar`, `Enum`, `JSON` | `string` (for `JSON`, a string of valid JSON) |
| `UUID` | `uuid.UUID` |
| `BigInt` / `Int` | `int64` / `int32` |
| `Bool` | `bool` |
| `Decimal`, `Money` | `decimal.Decimal` |
| `Timestamp`, `Date` | `time.Time` |
| `Bytes` | `[]byte` |

```go
package schema

import (
	"github.com/google/uuid"
	s "github.com/tobibamidele/lathe/schema"
)

// Generated code (the db package) calls GenerateProjectID on every insert while
// the id is still empty, so it can return a fresh value each row.
func GenerateProjectID() string { return "proj_" + uuid.NewString() }

func GenerateID() uuid.UUID { id, _ := uuid.New(); return id }

var Schema = s.New(s.Config{Dialect: s.Postgres, Output: "db"},
    s.Table("projects",
        s.Text("id").PrimaryKey().DefaultFunc(GenerateProjectID),
        s.Text("name"),
        s.Timestamp("created_at").DefaultNow(),
        s.Timestamp("updated_at").DefaultNow(),
    ),
)
```

The function must be **exported** (`GenerateProjectID`, not `generateProjectID`) and a plain package-level function: the generated package imports your schema package and calls it by name, so closures and method values have no name to call. `Export()` reports a bad `DefaultFunc` alongside every other schema problem.

Unlike `Default` and `DefaultNow`, `DefaultFunc` declares no server-side default: the column gets no `DEFAULT` clause in SQL, and a `DefaultFunc` field is always sent once the function has run. Generated code fills the field with `f()` whenever it still holds its zero value (`""` for strings, `uuid.Nil` for UUIDs, `IsZero()` for times) before the `INSERT` is built, in `Create`, `CreateMany` and `Upsert` — see [Writing data](/docs/writing). The value is known in Go on every dialect. Rows written by tools other than lathe have no database default to fall back on, so prefer `DefaultUUID()` unless you need the value produced by your own code.

A column has either a server-side default or a `DefaultFunc`, whichever was called last: `Default`, `DefaultNow`, `DefaultUUID` and `DefaultExpr` clear a `DefaultFunc`, and calling `DefaultFunc` clears them.
